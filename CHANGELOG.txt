================================================================
PV GENERATOR — CHANGE LOG
================================================================
A plain-English history of what changed in each version.
No technical knowledge needed.

Newest version is at the top.

----------------------------------------------------------------
VERSION 25 — "Auto-split signed PDFs + preview pane"
----------------------------------------------------------------
WHAT'S NEW
- A multi-page signed PDF is now split automatically into one entry
  per page.
- Click any signed page or supporting document to view it in a
  preview pane on the screen (no new tab needed).
- Each signed page is combined with all the supporting documents
  into its own PDF; several results download as a ZIP.

----------------------------------------------------------------
VERSION 24 — "Simple Combine PDFs; no PV ID in Voucher No."
----------------------------------------------------------------
WHAT'S NEW
- The VOUCHER NO. field on the PV is now left empty (the PV
  reference ID no longer appears there).
- PDF Page Swap is now a simple PDF combiner: upload signed PDF(s)
  and supporting documents, click Combine. Each signed PDF is joined
  with all the supporting documents, in upload order. No page
  splitting, no matching, no thumbnails. One signed PDF downloads as
  one PDF; several download as a ZIP.

----------------------------------------------------------------
VERSION 23 — "No more typed-in fields; upload docs straight onto a
signed page"
----------------------------------------------------------------
WHAT'S NEW
- PDF Page Swap no longer asks you to type in Business Unit, Due
  Date, Adjudication Number(s) or Amount for each signed page. Those
  fields are gone entirely — there's nothing to fill in any more.
- You can now upload supporting documents directly onto a signed
  page: click the new "+ Upload" button on a signed page's "Matched
  documents" area, or drag PDF files straight from your computer onto
  it. This uploads the file(s) AND matches them to that page in one
  step, instead of uploading to the Supporting Documents column first
  and then dragging them over.
- Dragging an already-uploaded document card from the Supporting
  Documents column still works exactly as before, alongside the new
  direct-upload option.
- Since there's no Business Unit field any more, the downloaded ZIP
  is now flat (no per-business-unit folders) — just one combined PDF
  per signed page.
- A signed page with no supporting documents matched is now
  highlighted (instead of a missing Business Unit) as a reminder
  before you generate.

----------------------------------------------------------------
VERSION 22 — "Transmittal (Excel) removed from PDF Page Swap"
----------------------------------------------------------------
WHAT'S NEW
- The Excel declaration list (Transmittal.xlsx) is gone. PDF Page
  Swap now only does the PDF-combining — signed page in front,
  matched supporting documents after — and packages the results into
  a ZIP grouped by business unit. No spreadsheet is produced.
- The tool is now called "PDF Page Swap — Combine Signed Pages" (was
  "— Signed PV Transmittal"), the button reads "Combine & Download"
  (was "Generate Transmittal"), and the downloaded file is named
  "Combined Signed PVs (date).zip" (was "Signed PV Transmittal
  (date).zip").
- The Excel library the app carried for this is no longer bundled,
  making the app a little smaller.

----------------------------------------------------------------
VERSION 21 — "Drag-and-drop matching in PDF Page Swap"
----------------------------------------------------------------
WHAT'S NEW
- Matching supporting documents to signed pages is now drag-and-drop
  instead of a tick-box list: drag a document card onto the signed
  page it belongs with, drag it onto a different signed page to move
  it there, or drag it back onto the Supporting Documents column to
  unmatch it. A ✕ button on each matched document does the same
  unmatch in one click. Nothing is ever matched automatically —
  every match is something you dragged there.

----------------------------------------------------------------
VERSION 20 — "Preview button in PDF Page Swap"
----------------------------------------------------------------
WHAT'S NEW
- Every signed page and supporting document in PDF Page Swap now has
  a "🔍 Preview" button (and the signed-page thumbnail itself is
  clickable) that opens the full-size PDF in a new tab. Since all
  the fields on a signed page are typed in by hand, this is the way
  to actually read the printed page while filling them in — the
  small on-card thumbnail was only ever big enough to tell pages
  apart, not to read.

----------------------------------------------------------------
VERSION 19 — "Name and Financial Year are now mandatory"
----------------------------------------------------------------
WHAT'S NEW
- Name and Financial Year are now hard-blocked before generating,
  the same as Business Unit and Due Date — the button stops with a
  clear message and can't be skipped if either is empty.
- Financial Year no longer remembers a previous value or defaults to
  the current year — it now always opens blank and must be typed in
  fresh every time. Name is still remembered between sessions as
  before.

----------------------------------------------------------------
VERSION 18 — "Breakdown files are excluded automatically"
----------------------------------------------------------------
WHAT'S NEW
- Any file with "(breakdown)" in its name is now automatically left
  out wherever files are uploaded — the PV Generator's per-line
  upload, and both upload zones in PDF Page Swap (signed pages and
  supporting documents). It's never classified, attached, or
  included in the ZIP; a status message says how many were left out.

----------------------------------------------------------------
VERSION 17 — "PDF Page Swap fields are now manual; PV Generator
opens with one blank line"
----------------------------------------------------------------
WHAT'S NEW

PDF PAGE SWAP
- Removed the automatic "Read (OCR)" / "Read all signed pages"
  reading from the signed-page cards. Testing (see Version 16 below)
  showed it could not reliably read the adjudication-number table
  even under ideal conditions, so rather than keep a feature that
  sometimes silently got it wrong, it has been taken out. Business
  Unit, Adjudication Number(s), Amount and Due Date are now plain
  typed-in fields for every signed page, same as everywhere else in
  the app.
- The checks before generating now simply flag a field as "not
  entered" rather than "not detected", since nothing is read
  automatically here any more.

PV GENERATOR
- Opening the PV Generator now starts with exactly one blank line
  item instead of five. Extra lines are added by hand with the
  "+ Add line" button as needed — this also makes the starting screen
  predictable for anyone driving the form with an automation tool
  such as Power Automate Desktop, which needs a consistent single
  starting row to click against.

----------------------------------------------------------------
VERSION 16 — "Honest OCR reporting on the signed page"
----------------------------------------------------------------
WHAT'S NEW
- Testing turned up a real limitation: the adjudication table on a
  signed PV packs a dozen near-identical 15-character codes into
  small, bordered print, and that is genuinely hard for OCR to read
  back reliably — even from a clean, freshly generated page, let
  alone a printed-and-scanned one. Business Unit, Amount and Due
  Date sit in larger, more isolated text and are unaffected.
- The reading step now makes a second, more targeted pass at the
  adjudication numbers with the OCR engine restricted to letters and
  digits only, which removes some dictionary-driven misreads, and
  renders the page at a higher resolution first. This helps in some
  cases but does not make table reading fully reliable — it remains
  a field worth double-checking against the printed page.
- When Business Unit / Amount / Due Date are read but the
  adjudication number(s) are not, the signed page now says so
  plainly instead of reporting a blanket "read automatically" — so a
  blank adjudication field doesn't get missed before generating.

----------------------------------------------------------------
VERSION 15 — "Signed PV Transmittal, mandatory business unit"
----------------------------------------------------------------
WHAT'S NEW

PV GENERATOR
- Business Unit (the Subsidiaries dropdown) is now mandatory before
  generating the ZIP — the button stops with a clear message if it
  hasn't been selected. This is a hard block, like the due date, and
  cannot be skipped. Previewing the PV does not require it.
- "Deleum Chemical Sdn Bhd" has been renamed to "Deleum Chemicals Sdn
  Bhd" throughout — the dropdown, the reference ID's subsidiary code
  lookup, and file names. A draft saved before this rename still loads
  correctly; the old name is converted automatically.
- Every voucher now also carries a small "Ref:" stamp at the bottom
  of the page, in addition to the existing VOUCHER NO. field at the
  top — the same reference ID in both places. This is what the new
  PDF Page Swap OCR (below) reads back off a signed, scanned copy.

PDF PAGE SWAP — rebuilt as "Signed PV Transmittal"
- The tool no longer swaps a single page into a single document. It
  now handles a whole batch of signed vouchers and their paperwork:
    1. Upload any number of signed/scanned PV PDFs. A multi-page scan
       is automatically split into one page each.
    2. Upload any number of supporting documents, unchanged.
    3. For each signed page, tick which supporting documents belong
       with it. Matching is manual for now — a future version will
       do this automatically using the reference ID above.
    4. Generating places the SIGNED PAGE IN FRONT of its matched
       supporting documents. Nothing in the supporting documents is
       ever replaced or removed (previously the tool replaced page 1
       of a single document — that behaviour is gone).
- New offline OCR step reads the signed page itself (not the
  supporting documents) to fill in the adjudication number(s),
  amount, due date and business unit automatically — every field
  stays editable in case OCR gets something wrong. Needs the app
  served over http(s), same requirement as the existing payment-
  amount OCR.
- Generating now produces a ZIP containing:
    - One combined PDF per signed page, sorted into folders by
      business unit.
    - Transmittal.xlsx — a summary sheet plus one sheet per business
      unit, listing every voucher's adjudication number, amount, due
      date and matched documents, with blank sign-off columns so it
      can double as the declaration list submitted to Finance and as
      a transmittal.

VERSION 14 — "Exemption notices"
----------------------------------------------------------------
WHAT'S NEW
- The app now handles a letter type that has no deadline sentence at
  all: an exemption notice, "NOTIS TAKSIRAN SEKURITI (PENGECUALIAN)".
  These are issued when the duty is waived, so there is no "sila
  jelaskan duti... selewat(-lewat)nya pada..." line to read.

- For this letter type only, the due date is taken from the letter's
  own issue date instead — the "Tarikh: dd/mm/yyyy" shown right next
  to the Nombor Adjudikasi at the top of the letter.

- All the other ways of finding a due date are unaffected and still
  checked first: a stated deadline on a normal letter, an approved
  Surat Rayuan, and the Borang Nyata's received-date-plus-30-days.
  The letter-date fallback only applies when none of those apply and
  the letter is confirmed to be this exemption type.

----------------------------------------------------------------
VERSION 13 — "Reference ID on every voucher"
----------------------------------------------------------------
WHAT'S NEW
- Every voucher now gets a short reference ID, for example:

      TSB-26-2108-60-01
      │   │  │    │  └ batch number (01, 02 ... when one due date
      │   │  │    │    needs more than one voucher)
      │   │  │    └─── total amount, whole ringgit
      │   │  └──────── due date, day and month
      │   └─────────── financial year, last two digits
      └─────────────── subsidiary short code

- The ID appears in three places so a voucher and its supporting
  documents can never be mixed up:
      1. In the "VOUCHER NO." box on the payment voucher itself.
      2. In a box at the top of the first page of the supporting
         documents.
      3. At the end of the supporting documents file name, in
         square brackets.
  It is also stored inside both PDFs' file properties, so Windows
  Search can find a voucher by its ID.

- Subsidiary short codes used in the ID:
      Deleum Berhad                       DB
      Deleum Services Sdn Bhd             DSSB
      Deleum Oilfield Services Sdn Bhd    DOSB
      Turboservices Sdn Bhd               TSB
      Turboservices Overhaul Sdn Bhd      TOSB
      Deleum Chemical Sdn Bhd             DCSB
      Deleum Technology Solutions Sdn Bhd DTSB

VERSION 12 — "Receipt confirmations and due date on the voucher"
----------------------------------------------------------------
WHAT'S NEW
- The app now recognises the receipt confirmation form
  ("PENGESAHAN PENERIMAAN BORANG NYATA DUTI SETEM") and files it
  under Additional Documents. Like the Surat Rayuan, it is spotted
  either from the file name or from the wording inside the PDF, so
  it works even if the file has been renamed.
  This matters because that form also carries its own "Nombor
  Adjudikasi" — without this it would have been mistaken for the
  main adjudication letter and taken its place.

- The Payment Voucher now shows the due date on the form itself.
  It appears as "Due Date: 16/09/2026" on the line directly below
  the last Nombor Adjudikasi and just above the "Payment for
  Lembaga Hasil Dalam Negeri (Stamp Duty)" line.

- Additional Documents now confirm what happened when you upload:
  the app reports how many were added and the running total, and
  quietly skips a file you have already attached to that line
  (same name and size) so nothing gets duplicated by accident.

REMINDER
- Additional Documents have always added to the list rather than
  replacing it, so uploading more supporting files at any time is
  safe — earlier ones stay attached.

----------------------------------------------------------------
VERSION 11 — "Appeal letters (Surat Rayuan)"
----------------------------------------------------------------
WHAT'S NEW
- The app now recognises an approved penalty appeal letter (Surat
  Rayuan). It spots one either by the file name containing "Surat
  Rayuan", or by finding the words "RAYUAN PENALTI DILULUSKAN"
  inside the PDF — so it still works even if the file is named
  something else entirely.

- Surat Rayuan letters are filed under Additional Documents. This
  matters because they also carry a "Nombor Adjudikasi", so without
  this they would have been mistaken for the main adjudication
  letter and taken its place.

- If a Surat Rayuan is uploaded, its deadline is used as the due
  date, because an approved appeal replaces the original deadline.
  It is read from the sentence:
      "Sila jelaskan duti yang kena bayar selewatnya pada 16/09/2026."
  If a due date had already been picked up from the original letter,
  it is updated automatically and the app tells you it changed, for
  example: "Surat Rayuan found — due date updated from 20/08/2026 to
  16/09/2026".

FIXED
- The two different wordings LHDN uses for the deadline are now both
  understood: "selewat-lewatnya pada ..." (adjudication letters) and
  "selewatnya pada ..." (appeal letters). Previously only the first
  was recognised, so appeal letters gave no due date at all.

REMINDER (unchanged, still working)
- Where no deadline is stated outright, the due date is still worked
  out from "Tarikh Permohonan Diterima" on the Borang Nyata plus 30
  calendar days.

VERSION 10 — "Clearer file names and built-in due dates"
----------------------------------------------------------------
WHAT'S NEW
- Added a "Financial Year" box at the top of the screen. You type
  the year once and it's used in all the file names. It remembers
  what you typed last time and defaults to the current year.

- Files are now named in a consistent, self-explanatory way:
      LHDN PV (FY2026) - Turboservices Sdn Bhd (12-09-2026).pdf
      LHDN PV (FY2026) - Turboservices Sdn Bhd (12-09-2026)
          - Supporting Document (RM 57.00).pdf
  The ZIP itself is named:
      LHDN PV (FY2026) - Turboservices Sdn Bhd.zip
  (no due date on the ZIP, since one ZIP can cover several dates).

- Every generated PDF now carries its details inside the file's own
  properties — due date, subsidiary, financial year, total amount
  and the adjudication numbers. You can see these in Adobe Reader
  under File > Properties, and Windows Search can find a voucher by
  its due date or adjudication number even if the file gets renamed
  or moved. Nothing extra is printed on the page itself.

- The financial year is also saved in your drafts.

VERSION 9 — "Smarter due dates and 10-line vouchers"
----------------------------------------------------------------
WHAT'S NEW
- The app can now work out the due date in two ways:
    * If the letter states the deadline outright ("selewat-lewatnya
      pada ..."), it uses that.
    * Otherwise it reads "Tarikh Permohonan Diterima" from the
      Borang Nyata form and adds 30 calendar days automatically.
  Either way the due date fills in on its own — no typing needed.

- A voucher now holds a maximum of 10 lines, because that's what
  fits on the printed form. If a due date has more than 10 items,
  the app automatically splits them across several vouchers:
      lines 1-10  -> PV 1
      lines 11-20 -> PV 2
      lines 21-30 -> PV 3, and so on.
  Line 11 will never be squeezed onto the same voucher as the first
  ten. Each voucher keeps the correct due date and its own totals.

- When a due date needs more than one voucher, its folder now
  contains a subfolder per voucher ("PV 1 of 2", "PV 2 of 2"), each
  holding that voucher's own PDF, supporting documents and list.
  Due dates that only need one voucher stay as a single flat folder,
  exactly as before.

CHANGED
- The notepad (.txt) file is now a clean list of adjudication
  numbers only — one per line, with no numbering, no amounts and no
  headings — so it can be copied straight into other systems.

================================================================
HOW TO RUN THE APP
================================================================
There are two ways, depending on which version you have:

1. FROM A WEB LINK (if hosted on GitHub Pages)
   Just open the link. Nothing to install. All features work.

2. FROM A FOLDER ON YOUR COMPUTER
   - Best: double-click "Start_PV_Generator (Windows).bat"
     (or the Mac/Linux version). This enables every feature,
     including automatic reading of the payment amount.
   - Quick: double-click "index.html". Everything works except
     the automatic payment-amount reading — you type it yourself.

In every case the app runs on your own machine and your documents
are never sent anywhere.
